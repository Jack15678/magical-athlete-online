# 沉浸式赛场、自己练习与人机验收

更新：2026-10-21。

比赛时，3D 赛场占满当前视口。菜单收纳画质、声音、动画速度、帮助、积分、播报和房间管理；屏幕上保留视角控制、小地图、紧凑选手头像、行动提示与掷骰或技能选择。普通格和角色均放大；魔法赛道使用覆盖整格的金色加分星、红色绊倒警告、绿色前进箭头和紫色后退箭头，配合立体标识与触发反馈。

默认「自己」聚焦自己的棋子。其他选手的同一次移动与技能连锁共享镜头，完整结束后停留再回到自己；两人双角色模式会优先返回即将行动的自己的棋子。「总览」保持全景。拖动平移或滚轮、双指缩放会暂停跟拍，点击「回到自己」恢复；「镜头」中的「自动观看他人行动」默认开启。需要自己选择时，相关棋子与选择界面优先于无关演出。

首页「自己练习」由一名真人独自选择角色、掷骰和使用技能，不需要其他玩家；兔子在无其他活跃选手的单人练习中允许正常移动，界面和日志明确说明这一练习例外。首页「人机对战」可选 1～7 位 AI；AI 使用服务器投影给该玩家的信息完成选秀、暗选、掷骰和技能选择，沿用正式裁定。每场结算后由真人点击前往下一场，四场结束显示总成绩。

## 验证方法

- `tests/browser/immersive-practice.spec.ts` 使用隔离的 Node 内存服务设置确定性局面，再通过真实 UI 提交掷骰与技能选择。检查实际 3D 相机位置、缩放、俯视角、连续事件、手动拖动和滚轮、跟拍开关、总览以及自己的选择优先级。
- `tests/relay-browser/solo-ai.spec.ts` 使用真实 Worker 中继与浏览器计算房主，从首页创建新房间。测试只读 IndexedDB 判断当前阶段，所有真人动作均由实际按钮完成，AI 动作由权威调度完成。
- 保留并复验现有 3D 默认掷骰停稳、重连不重播、同时移动、跳过与移动端设置专项；没有将显示动画当成规则或服务器裁定。

桌面视口为 1440×1000，手机视口为 390×844，均在 Windows Edge 实际渲染；检查棋盘边界与页面双向滚动尺寸。手机结论属于浏览器尺寸模拟，未声称覆盖真实手机 GPU、系统安全区硬件或所有浏览器。

## 复现

```sh
pnpm build
pnpm exec playwright install ffmpeg
pnpm exec playwright test tests/browser/immersive-practice.spec.ts --output test-results/immersive-run
pnpm exec playwright test tests/browser/three-scene.spec.ts --grep "3D dice settles|3D simultaneous" --output test-results/three-scene-run
pnpm exec playwright test -c playwright.relay.config.ts tests/relay-browser/solo-ai.spec.ts --output test-results/solo-run
```

并行运行时应使用不同的 Playwright 输出目录，避免清理其他运行的 trace。中继进程也应独立启动或使用不同端口；不要让另一套测试的自动清理关闭正在验收的中继。

上述各次通过运行均为 **0 页面脚本错误**。完整人机实测使用 4 倍速、减少动效、低画质；相机专项保留默认 1 倍速和完整演出，默认掷骰仍为约 2.5 秒。AI 四场测试没有修改随机结果、角色、位置或规则，只读存档用于识别操作者。相机专项使用隔离测试服务中的可复现局面，镜头和动画没有提交规则动作。

最初一次人机验收在第四场时，复用的本地中继被另一套测试的退出清理关闭，未计为通过；改用独立 8788 端口与独立存储后，重新从首页完整完成上述四场。早期缺少视频编码器、并行输出目录清理和双角色回位测试预期的问题也已分别修正后重跑。
