访问日期：2026-10-20。非官方好友房项目；原作标识、角色原画和商业字体不随网站分发。

## 设计令牌与布局

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 运动黄 | `#ffda27` | 页面底色、当前行动、选中状态 |
| 发令红 | `#f44735` | 主要操作、重要比赛阶段 |
| 跑道蓝 | `#254de4` | 页眉、侧信息、选秀背景 |
| 墨黑 | `#191919` | 轮廓、文字、按钮影子 |
| 纸白 | `#fffdf4` | 可读的角色技能、表单和棋盘格 |
| 草地绿 | `#b5d66b` | 完成、在线、轻松赛道 |

字体使用本机 `Microsoft YaHei` / `PingFang SC` 中文无衬线，英文标题使用本机 `Arial Black`，不请求境外字体服务。标题紧密、粗重、有轻微旋转；技能正文保持水平和足够行距。

首页由超大中文标题和原创角色群建立主题，创建和加入保持一个清楚的操作区。房间以赛道为中心：上方显示阶段和邀请，右侧为分数与日志，底部为当前操作。选秀由大头像卡和完整中文技能组成。规则、设置与细节按需展开，比赛时不覆盖赛道。

3D 赛道固定两处直角转弯：0→12 格沿上段前进，12 格第一次转弯，15 格第二次转弯，再沿下段到 30 格终点。手机将同一块棋盘整体旋转 90°，保留格序和两个转角。每格分散放置棋子，同格角色保留独立座位数字和玩家色。另列出全部运动员的位置、所属玩家、绊倒和出局状态，点击棋子可读技能；不靠颜色或悬停传达必要信息。

36 个头像使用原创 SVG 几何插画：统一粗描边、圆端点、纸白眼睛、不渐变；各自具有不同主体轮廓和技能提示物。头像组件供角色卡和选手列表复用。赛道棋子改为对应的原创 3D 玩具雕塑，以体积、塑料材质、光照和阴影表现，保留兔耳、香蕉、房屋、飞艇、火箭等辨识轮廓。玩家色用于底座、外圈与座位牌，角色自身配色不表示玩家。

动效解释掷骰、逐格移动、传送、交换、绊倒和技能连锁。正常速度掷骰约 2.5 秒，停稳点数服从权威结果，再衔接棋子移动。全局提供低画质、静音、减少动效和 1×/2×/4× 速度；减少动效初始遵循系统偏好。声音默认关闭，只有主动开启后才由浏览器合成简短提示与骰子碰撞声，无外部音效资源。

## 工具核验

本机项目：React 19、Vite 7、TypeScript 5、Socket.IO 4；3D 场景采用 Three.js、React Three Fiber 与 Drei（精确安装版本见锁文件）。原始 SVG、CSS 和几何雕塑源在项目内编写。

2026-10-20 实际阅读以下官方仓库 `main` 分支原文，作为设计指导；并未声称它们已安装为本机 skill。仓库未在这些文件中提供版本号，故以访问日期标识快照：

- [OpenAI game-ui-frontend](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/game-ui-frontend/SKILL.md)：采用先定视觉方向、保护比赛区域、DOM 承载文本、响应式、减少动效等适用于 2D 桌游的要求。其 3D 摄像机和 pointer-lock 部分不适用。
- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：采用先设令牌、从题材出发、字体层级、克制动效和截图复查的要求。遵循其 LICENSE.txt 链接的原仓库许可；项目代码和资产为新编写内容。

2026-10-21 的 3D 升级按实际 React 技术栈阅读并采用 [react-three-fiber-game](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/react-three-fiber-game/SKILL.md) 和 [web-3d-asset-pipeline](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/web-3d-asset-pipeline/SKILL.md)：场景与规则状态分离、DOM 承载技能文字、独立镜头控制、GLB 导出、材质复用与 Meshopt 优化。具体实现见 [3D升级说明](./3d-upgrade.md)。

本项目视觉判断：原色来自用户明确方向和桌游题材，不采用通用仪表板式均匀卡片。将视觉表现集中在玩具角色与两处直角的赛道，表单和操作保持安静、清楚。

## 2D 版本的历史视觉复查

以下保留升级前的界面、联机与弱网检查记录，其中蛇形排版与截图不代表当前 3D 棋盘。3D 版本的最终浏览器验收结果统一记录在 [测试报告](./testing.md)。

2026-10-21 使用项目的 Playwright 与本机 Microsoft Edge 无头浏览器，检查 1440×1080 桌面与 390×844 手机视口，实际生成并查看首页、大厅、选秀及比赛页截图。截图位于本地 `tmp/{home,lobby,draft,race}-{desktop,mobile}.png`。

八人比赛页使用独立角色的视觉夹具，将全部八枚棋子置于起点检查拥挤情况；这项检查只证明布局，不充当完整联机流程或规则验收。手机页面实际测得 `scrollWidth = innerWidth = 390`，起点渲染八枚棋子，浏览器页面错误为零。卡片长技能正文保持完整，可点击展开；手机赛道改为四列，避免整页横向溢出。

复查后补充：复制失败时给出可选中的手动复制窗口；弹窗在实时快照更新时保持键盘焦点；赛道特效直接读取共享数据，未核验赛道显示明确说明。TypeScript 检查与 Vite 7.3.7 生产构建均通过。

2026-10-21 第二轮复查：狂野十个特殊格补证后全部显示，手机空格高度由91px降至64px，四枚以上同格仍展开到96px以上。实际390px视口量得赛道高度669.5px、整页宽度390px、起点八枚棋子全部存在，页面错误仍为零。新增截图 `tmp/race-wild-mobile.png` 与 `tmp/rules-mobile.png`。规则弹窗直接打包公开房规源文件全文，不要求玩家访问私有仓库；首页操作时限默认120秒。上述检查仍属于界面视觉夹具，完整多人对局由独立联机测试记录。

浏览器房主主方案接入后，新增可见的“计算房主”说明，明确原浏览器标签页应保持打开、完整存档只存在该浏览器；游戏管理权与计算资格分别说明。访客在计算页离线时看到等待提示，操作禁用；连接恢复后，必须收到与主动同步请求对应的最新本人快照，才启用操作，避免认证刚完成时用旧缓存版本操作。

2026-10-21 使用本机Edge对真实本地Workers中继8787执行独立双身份短验收：同创建者两标签只有一个Web Lock，关闭原计算标签后同浏览器另一标签接管，接管后立即准备成功；关闭全部计算页后访客等待且无法选牌；原浏览器返回恢复已确认的选秀游标与手牌，其他身份快照未包含他人hand/selection字段，页面错误为零。实际查看390px截图`tmp/browser-host-mobile.png`。这项检查补充主测试报告的四场多人验收，不将短验收替代完整对局。

计算锁采用[Web Locks官方平台说明](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request)中的独占、`ifAvailable`及异步回调生命周期，不使用`steal`抢占健康计算页。网络层只传操作意图及每人私有快照，完整状态与未来随机信息不发送给访客。

同日最终弱网验收：对真实8787中继使用[Playwright WebSocket双向拦截](https://playwright.dev/docs/api/class-websocketroute)，保持连接两端打开但丢弃房主全部帧，模拟幽灵连接。客户端每10秒ping，25秒无pong主动换代；中继35秒租约在本次测得35,107ms后以4408撤销失联计算连接。访客等待提示出现且选牌禁用，放通后原锁与IndexedDB实例重新同步，已确认选秀游标、本人手牌不变。另用浏览器offline/online事件验证已知断网立即停操作、恢复重新认证；每次计算身份重认证只刷新一次完整操作时限，普通成员上下线不延长时限。原有双标签接管与私有视图验收同时通过，页面错误为零。
