# 3D 棋盘与动画架构

本次升级保留 `src/engine` 规则引擎、浏览器计算房主、Node 房间服务和现有 Cloudflare 部署流程。React 界面新增 React Three Fiber 场景，棋盘、棋子、骰子和主要特效使用真实 3D 网格；规则文字、分数和操作按钮继续由 DOM 承载。

## 固定两处直角的赛道

31 个位置始终连接为同一条 U 形赛道：从 0 格向右到 12 格，第一次直角转弯；沿连接段到 15 格，第二次直角转弯；再向左到 30 格终点。坐标映射集中在 `src/client/scene/math.ts`，两处转角是 12、15 格。移动逐格读取同一坐标函数，棋子不会穿过赛道中央或跳过转角。

手机把这块棋盘整体旋转 90° 并重新适配镜头，格序、距离和两个转角保持一致。格子与棋子一起放大，多人同格分散到稳定网格，保留各自造型、玩家色环和座位数字。棋盘铺满可用视口，默认固定斜俯视聚焦自己的选手；手动平移和缩放暂停跟拍，一键回到自己。总览模式保持完整31格赛道，通过高亮提示行动者。

## 权威状态与演出队列

`presentation.ts` 只消费已确认的 `RoomView` 与事件日志，不掷骰、不修改规则队列，也不替权威端提交动作。Node 模式由服务器确认规则结果；正式浏览器房主模式由持有计算锁的房主页面确认，Workers 负责中继。两种模式复用同一套表现代码。

| 模块 | 职责 |
| --- | --- |
| `src/engine`、房间服务 | 规则结算、随机结果、合法选择、事务与持久化 |
| `src/client/presentation.ts` | 从确认日志生成掷骰、移动、技能等演出片段 |
| `src/client/usePresentation.ts` | 本地播放时钟、速度、跳过和重连恢复 |
| `src/client/scene/Board3D.tsx` | 棋盘、镜头、棋子插值、骰子特写与特效 |
| `src/client/scene/ToyCharacter.tsx` | 缓存模型加载、归属底座与画质设置 |
| `src/client/App.tsx` | 可操作阶段、技能选项、分数和可读提示 |

演出游标记录已经接收的最高事件 ID，包含尚在排队的事件；重复快照不会重复排入。同一日志窗口按事件 ID 排序并去重。掷骰事件 `die` 与稍后确认的 `roll` 只形成一次演出，重新掷骰则使用新的事件 ID。带相同 `group` 的连续移动或传送合并为同一片段，全部目标同时完成；后续技能仍按规则日志顺序展示。

首次进入房间、断线重连、换场、角色集合变化或日志窗口缺失时，从最新确认局面重建表现基线，避免回放旧骰子或用不完整日志猜测位置。普通移动逐个访问真实赛道格；后退、传送、交换、绊倒、起身、得分和冲线分别具有不同片段。每个片段结束后一起提交该片段的显示位置，队列清空时与确认快照对齐。

规则结算不等待动画帧率。加速和“跳过动画”只影响当前浏览器的演出；跳过直接显示最新确认局面。演出期间提示发动者和事件过程。同一回合的移动、技能与反应共享镜头链，结束停留700毫秒后回到自己；单链预算9秒、总待播队列11秒，压缩未开始片段，当前片段时钟保持稳定。需要自己选择时，无关旧演出快进到已确认局面，优先展示合法对象与技能面板。掷骰按钮仅在当前选手进入掷骰阶段且相关演出完成后可用。

## 2.5 秒掷骰特写

正常速度的一次掷骰持续 2,500 毫秒。独立 3D 骰盘展示抛出、空中旋转、落地弹跳、滚动收敛和停稳，最后一小段突出点数，再衔接移动。碰撞声由 Web Audio 实时合成，静音时不播放。

骰子使用确定的运动学演出：权威结果确定最终朝向，时间曲线只控制飞行和衰减弹跳。六面点数对应独立网格，`diceTopRotation` 把已确认骰面的法线旋转到世界坐标 +Y。动画没有第二套随机结果，也不以落地姿态决定移动距离。骰面与能力修正后的移动距离分别显示。

## 资产、性能和设置

36 个棋子为本项目原创的几何玩具雕塑，保留已有 SVG 头像的角色轮廓和色彩。真实体积、统一塑料材质、场景光照和贴地阴影构成卡通玩具风格。`public/models/toy-racers.glb` 为 glTF 2.0，使用 glTF Transform 去重、清理与 Meshopt 压缩，整套约 455 KiB，无纹理和外部模型请求。模型数据缓存后由实例共享，详见 [3D 资产管线](./3d-assets.md) 与 [资产与许可](./assets.md)。

场景按需渲染静止棋盘，演出时连续更新；手机限制像素比。低画质降低渲染像素比、关闭阴影和部分装饰。设置提供静音、减少动效以及 1×、2×、4× 动画速度，并保存在本机。声音默认关闭；减少动效的初始值遵循系统偏好，启用后缩短演出并取消主要跳跃、翻滚和自动镜头移动。

模型解码器随应用打包，不使用 CDN；内容安全策略仅增加 `script-src 'wasm-unsafe-eval'` 以允许 Meshopt 的 WebAssembly 初始化。图形上下文丢失时显示恢复入口，角色列表和已确认房间状态仍由普通界面承载。

## 操作与可访问内容

鼠标拖动平移，滚轮缩放；触屏拖动平移、双指缩放。镜头角度固定，动作链以平移和适度缩放呈现。点击棋子可查看技能；全部角色也能通过普通按钮进入详情。键盘使用 Tab 访问掷骰、技能选择、设置、角色详情和恢复视角等 DOM 按钮，Enter 或空格激活，选择框支持标准键盘操作。

技能正文、分数、阶段与等待原因使用可读的覆盖层和普通文本；棋盘另提供包含角色位置、绊倒状态的屏幕阅读器列表。归属同时使用玩家色与座位数字。必要规则和操作不依赖悬停或辨认 3D 模型。

## 实施指导与验证入口

实际技术栈为 React，采用 [react-three-fiber-game](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/react-three-fiber-game/SKILL.md) 的场景与规则分离、DOM 界面和独立镜头原则；模型遵循 [web-3d-asset-pipeline](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/web-3d-asset-pipeline/SKILL.md) 的 GLB、共享材质、优化、轴心与运行时验证要求。原生 [three-webgl-game](https://github.com/openai/plugins/blob/main/plugins/game-studio/skills/three-webgl-game/SKILL.md) 是技术栈选择参考，当前没有并行引入另一套原生游戏循环。

资产解码检查位于 `tests/3d-assets.test.ts`，骰面朝向与赛道坐标检查位于 `tests/scene-math.test.ts`，事件同步检查位于 `tests/presentation.test.ts`，浏览器场景检查位于 `tests/browser/three-scene.spec.ts`。最终桌面、手机、多人、重连与部署验收结果统一记录在 [测试报告](./testing.md)；本文件描述实现，不代替实际验收结果。
