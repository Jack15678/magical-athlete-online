# 房间聊天、昵称与旧局兼容

实现日期：2026-10-21。

房间聊天复用原有 Socket.IO / Durable Object WebSocket。消息由房间服务分配递增 ID、发送时间和发送时昵称，客户端只提交 `clientMessageId` 和纯文本。最近 100 条消息保存在房间存档中；重连可按消息 ID 补齐。选秀、比赛、技能等待、动画和四场之间切换不影响聊天；计算房主离线时，中继仍可接受当前房间成员聊天。

每个真人身份在 10 秒内最多发送 6 条消息，正文去除首尾空白后为 1～500 个 UTF-16 单元；拒绝不可见控制字符。相同发送者和 `clientMessageId` 的重传使用持久回执，原编号不能发送不同正文。回执与房间存档原子提交，失败不广播成功。消息历史和回执随房间解散、过期清理。

成员验证依赖稳定 ID 和原有令牌。观战者认证后可聊天；机器人不能发送真人消息；其他房间、退出后已撤销身份和未认证连接不能读取或发送本房间记录。历史消息保存发送时昵称，同时保留发送者稳定 ID。

昵称统一去除首尾空白并以 NFKC 规范化；重名比较忽略字母大小写和全半角差异。玩家、机器人和观战者共用命名空间。追加最小可用正整数后缀，必要时缩短原名以保持 20 字上限；其他成员退出不会触发重排。Node 使用同步事务；中继使用房间串行队列和持久事务，因此同时加入或改名不会分配重名。

真人参赛者从对局开始至四场终局共可成功改名一次。空昵称、超长、控制字符、相同最终名称或写入失败不扣次数；自动分配重名后缀不扣次数。重复提交同一个成功请求返回原回执。改名更新当前成员名称并追加系统聊天，历史聊天不会被改写。次数保存在稳定玩家身份中，刷新、重新认证和中继重建不会恢复；只有成功确认“再来一局”重置。观战者目前可以加入时选择昵称，不提供局内手动改名。

客户端接口：

- `chat-send({clientMessageId,text})`：`ChatReply`。中继协议另带传输用 `requestId`。
- `chat-sync({afterId})`：`{messages,latestId}`，最多 100 条；认证时主动同步。
- `rename({requestId,name})`：`RenameReply`，返回实际分配名称和剩余次数。
- `chat` 事件：`{messages,latestId}`，完全独立于游戏局面版本。
- 局面含 `chat`、`chatLatestId` 和本人的 `renameRemaining`；中继成员元数据含 `renameUsed`。

新局的角色牌池在创建时固定为 `original`、`second-wind` 或 `mixed`，默认原作。房间投影展示保存的 `rulesVersion`。`src/engine/runtime.ts` 根据版本选择实际引擎：新局使用 `cmyk-base-aug2026-sw-transcript-v1`；更新前没有版本字段的存档固定为 `legacy-base-v1`，继续使用保存于 `src/engine/legacy-v1.ts` 的原作引擎和 36 张牌池。重新开局才切换当前规则。未知版本不会被当前引擎结算，仍可读取、聊天和解散。

验证涵盖 Node 内存/SQLite 存档、中继真实处理函数、模拟持久存储失败、中继重建、权限拒绝、历史 100 条、持久重传去重、同时加入/改名、跨分赛保留、一次改名、新局重置和未知规则版本拒绝。真实 Socket.IO 回归另覆盖聊天或改名已经提交、但广播前恰好达到房主离线截止的边界：正常关闭并清理房间及回执，不发布关闭后的聊天，也不抛出未捕获异常。网页交互验证另见本轮浏览器测试结果。
